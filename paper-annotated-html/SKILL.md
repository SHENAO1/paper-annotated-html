# 论文双栏批注 HTML

输入一篇论文 PDF，输出一个可以离线打开的 `.html` 文件，结构如下：

- **页头**：深海军蓝导航栏，显示标题、课程信息，以及可点击开关的五色图例。图例旁有"中文译文"和"批注栏"两个开关。
- **章节导航条**：吸顶，点击跳转，滚动时高亮当前章节。
- **主体每段一行**：
  - 左栏依次是英文原文（Lora 字体，五色高亮）、1px 分隔线、中文意译（米色底 `#f0ece2`，左侧细线）；
  - 右栏是批注卡片：段落功能、逻辑角色、论证技巧、潜在漏洞，再加一个骨架阶段标签；卡片左边的颜色取该段的主色。
- **图、表、公式**：随原文出现。图表是截图，可以选择把表格转写成 HTML 表；公式用 KaTeX 渲染。
- **底部论证结构总览**：
  - 五步逻辑骨架，每步可点击跳回原文；
  - 一句话核心主张；
  - 论证最强处与最弱处；
  - 主张与证据对照表；
  - 术语表。
- 移动端自动变为单栏，也可以打印。

页面的版式、样式和交互都已经写在 `assets/template.html` 里。你要做的是**校对原文、写批注数据**，再用脚本构建。不要手写 HTML。

## 一次做完，自己分批

用户通常只说一句"把这篇论文做成双栏批注 HTML"。这就是完整的指令，按下面的流程**从头做到尾**：

- **不要中途停下来问用户**：不问"要不要继续""先看看预览吗"，也不问可以用默认值解决的问题（课程信息没给就留空，体裁自己判断）。只有找不到 PDF 或 PDF 是扫描图、抽不出文字时才问。
- **分批由脚本给出**：`build_html.py WORK --status` 会按篇幅把全文切成若干批（每批约 1800 词、不超过 12 个条目），并告诉你下一步做什么（`NEXT:` 行）。每批的原文用 `--dump` 打印出来，写完这几节的批注再进入下一批。不要一次读入全文再一口气写完，也不要把一节拆到两轮里写。
- **每完成一步就落盘**：批注写进 `annot/S{n}.json`，进度标记写进 JSON（`source.json` 的 `"proofread": true`、`meta.json` 的 `"overview_final": true`）。所以即使上下文被压缩或会话中断，重新运行 `--status` 就能接着做，已完成的批次不要重写。
- **每批之间只汇报一行进度**，比如"第 3/8 批完成（S7）"，然后直接开始下一批。

## 文件与命令

本技能目录（即这份 SKILL.md 所在的目录，下文记作 `$SKILL`）包含：

- `scripts/extract_pdf.py`：PDF → `source.json` 草稿、页面图、图表截图。也可以单独重新截取某张图。
- `scripts/build_html.py`：
  - `--status`：查看进度、分批方案和下一步；
  - `--dump S4-S6`：打印这几节校对后的原文（带条目 id）；
  - `--check`：只校验；
  - 不加参数：正式构建；
  - `--allow-partial --sections`：预览部分章节。

  正式构建（无错误、不带 `--allow-partial` / `--sections`）成功后，会在工作目录里写 `built.json`，记下生成的 HTML 文件名，作为"已完成"的标记。
- `scripts/organize_papers.py LIBRARY [--dry-run]`：整理论文库，把论文分成 `done/`（已用本技能完成）和 `todo/`（未完成）两部分，见第 7 步。
- `assets/profiles.json`：三种体裁的图例文字。
- `assets/template.html`：页面模板。
- `references/`：
  - `dimensions.md`：选体裁、五色怎么标，**标高亮前必读**；
  - `translation.md`：译文风格，**写译文前必读**；
  - `annotation.md`：批注和总览的写法，**写批注前必读**；
  - `data-format.md`：JSON 格式、校验规则，**写 JSON 前必读**。

这四份参考文件在开始第一批批注前读一遍即可，之后每批不必重读。

依赖 Python 3.9+、`pymupdf`，以及可选的 `pillow`（用于压缩图片）。缺少时执行 `pip install pymupdf pillow`。Windows 下脚本会自动把输出设为 UTF-8。

## 工作流程

### 0. 确认输入

- 找到 PDF。如果用户只给了文件名，就在当前目录里找；当前目录下有 `papers/` 论文库时，也到 `papers/todo/` 里找。
- **已有工作目录就续做**：如果 PDF 旁边已经有 `<slug>_work/`，先运行 `--status`，从 `NEXT:` 指出的步骤继续，不要重新抽取（重新抽取会覆盖校对结果）。
- **课程信息**：用户提到了就写进 `meta.json` 的 `course`；没提到就留空。
- **范围**：默认处理正文全部章节。参考文献、致谢、基金信息、作者简介、附录不做批注，校对时直接删掉；附录除非用户要求才保留。

### 1. 抽取

```bash
python $SKILL/scripts/extract_pdf.py "paper.pdf"            # → <pdf目录>/<slug>_work/
```

先读 `extract_report.txt` 和 `source.md`。报告会列出以下几类问题：

- 版式判断（单栏还是双栏）；
- 未拼接完整的段落；
- `⟨?⟩` 的数量；
- 被丢弃的行，按类型分别统计。

### 2. 校对（必须做，质量的一半在这里）

抽取结果只是草稿。校对时打开 `pages/page-NN.png`，逐页对照 `source.json`：

- **段落边界**：被分页或插图截断的段落要合并（报告里的"unfinished paragraph"），被误合并的要拆开。
- **标题层级**：检查每节的 `title` 和 `level`。误识别成正文的标题要提出来，误识别成标题的正文要并回段落。"Keywords" 这类行应改为 `kind: "keywords"`，并入摘要所在的节，不要单独成节。段首的行内小标题（如 "Data collection."）留在 `text` 里，同时写进该条目的 `runin` 字段，渲染时会加粗。
- **`⟨?⟩`**：对照页面图，改成正确字符（Ω、μ、≤、希腊字母等）。
- **公式**：每个 `equation` 条目都要对照图片写出 `latex`。正文中的行内公式符号如果抽成了乱码，也要修正。
- **图表截图**：逐个打开 `figures/*.png` 检查：有没有截掉内容，有没有混进正文或相邻的图。截得不对就重新截：

  ```bash
  python $SKILL/scripts/extract_pdf.py crop "paper.pdf" --page 4 --bbox 300,80,560,290 --save WORK/figures/F2.png
  ```

  坐标默认是 PDF 点；加 `--px` 则按 `pages/page-NN.png` 上的像素坐标。截完同步更新 `source.json` 里的 `bbox`。
- **元数据**：在 `meta` 里补全 `authors`、`venue`、`year`，它们都显示在页头。
- **丢失的内容**：报告里被丢弃的 `small` 行（脚注、表格单元格）中如果有正文内容，就补回去。

校对完成后，在 `source.json` 顶层加上 `"proofread": true`。从此 `source.json` 中的 `text` 就是"原文"，高亮短语要从这里逐字复制；`source.md` 是抽取时的旧稿，不再使用，看原文用 `--dump`。

### 3. 通读、定体裁、写总览草稿

1. 通读全文（`--dump` 不带参数打印全部），按 `references/dimensions.md` 选定体裁（`argument` / `empirical` / `design`）。
2. 写 `WORK/annot/meta.json`，包括 `profile`、`title_zh`、`course`、`glossary`（8–20 个关键术语），以及 `overview` 的草稿。
3. 先想清楚全文的论证链：问题是什么、主张是什么、证据是什么、作者回应了哪些反驳、得出什么结论。之后每段的"逻辑角色"都要挂在这条链上。总览草稿就是后面各批共同的参照，上下文被压缩后也靠它找回全局。

### 4. 分批批注

循环执行，直到 `--status` 不再提示批注：

1. `python $SKILL/scripts/build_html.py WORK --status`，看 `NEXT:` 给出的这一批是哪几节。
2. `python $SKILL/scripts/build_html.py WORK --dump S7-S8`，读这一批的原文。需要时再看一眼 `meta.json` 的总览草稿和术语表，保持术语和论证链一致。
3. 每节写一个 `WORK/annot/S{n}.json`（格式见 `references/data-format.md`）。每个段落都要有以下三样：
   - `hl`：2–4 处高亮，每处是 `[逐字短语, 颜色]`，颜色含义随体裁而定；
   - `zh`：完整意译，遵循 `references/translation.md`；
   - `note`：`func` / `role` / `craft` / `gap` / `stage`，遵循 `references/annotation.md`。

   图注和表题都要翻译，公式要补 `latex`。
4. `python $SKILL/scripts/build_html.py WORK --check`，修掉这一批里的错误（"短语找不到"之类），再回到第 1 步。还没写的批次报出的"no annotation entry"错误是正常的，留到后面。

### 5. 修订总览

全部段落写完后，回到 `meta.json` 修订 `overview`：

- 骨架每一步的 `refs` 指向真实的段落；
- 最强处和最弱处要和段落批注里的 craft、gap 相互呼应；
- `claims` 表写 3–6 条。

修订完在 `meta.json` 顶层加上 `"overview_final": true`。

### 6. 构建与检查

```bash
python $SKILL/scripts/build_html.py WORK          # 默认输出 <pdf目录>/<标题>.annotated.html
```

- **错误**必须清零，构建脚本只有在没有错误时才会写出文件。
- **警告**逐条判断：
  - 译文过短，回去补译；
  - 译文残留英文单词：能译就译；必须保留的术语写成"中文（English）"；作为研究对象讨论的英文词加引号；
  - 高亮过多，删减；
  - 某种颜色从未使用，确认论文里确实没有这一维度；
  - craft 重复，改写。
- 有浏览器工具时打开页面看一眼，确认以下几点：
  - 高亮分布是否合理；
  - 图片清晰，没有截歪；
  - 公式正常渲染；
  - 总览的链接能跳转；
  - 窄屏下是单栏。

### 7. 归档与交付

**归档**：如果 PDF 在论文库里（所在目录是 `todo/`，或者它的上一级目录里同时有 `todo/` 和 `done/`），构建成功后运行：

```bash
python $SKILL/scripts/organize_papers.py <论文库目录>
```

脚本会把这篇论文的 PDF、工作目录和 HTML 一起移到 `done/<slug>/`，散放在库根目录的新 PDF 归入 `todo/`，最后列出两部分各有哪些论文。PDF 不在论文库里就跳过这一步。

告诉用户以下几件事：

- 输出文件的路径（归档过的话是 `done/` 里的新路径）；
- 选了哪种体裁及理由；
- 篇幅统计（几段、几张图）；
- 两三条最值得注意的发现，比如最弱处；
- 剩余的不确定之处：校对时没把握的符号、截图，或者跳过了哪些章节。

## 版权与分享

论文原文受版权保护，生成的 HTML 里包含全文和图表，**只作个人学习的本地文件**：

- 不要发布成公开网页或公开分享链接，页脚已经写明这一点；
- 用户要求分享时，提醒他们注意版权，并建议只分享批注和总览部分，或者分享开放获取（OA）论文；
- 不要把 PDF 或生成的 HTML 提交到公开仓库。

## 质量底线

- 原文一个字都不能改：高亮靠逐字匹配，校对也只修正抽取错误，不润色原文。
- 每个段落都要有译文和批注，不要偷懒写成"同上"。分批是为了每批都写得一样认真，后面的批次不能比前面的潦草。
- 批注要具体到这一段，像"论证清晰""数据充分"这种放到哪篇论文都成立的话不要写。
- gap 要公允。作者在后文回应过的问题，要注明在哪里回应的。
